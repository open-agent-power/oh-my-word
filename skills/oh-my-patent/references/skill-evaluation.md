# Skills 行为评测与发布依据

维护者修改触发描述、路由、领域披露或资料策略时使用。案例入口：[路由案例](../../../evals/skill-routing-cases.yaml)。可执行的冻结任务包、Codex CLI 运行和证据评分汇总见 [维护工具](../../../docs/skills-maintenance.md)。实现执行器不代表案例已评测；真实结果以运行目录及复核证据为准。

## 分开测三个问题

1. **宿主触发**：只让被测环境看到正常可发现的 name/description 和请求，观察是否读取主 Skill。显式要求使用主 Skill 的实验不能证明自动触发。
2. **领域路由**：主 Skill 已载入，检查实际读取的模块、遗漏和无关加载。不能只看最终回复自称使用了什么。
3. **产物质量**：实际输入材料与输出逐项比对，评审无依据事实、特征支持、公开充分性和修改成本。目录/JSON 合法不能替代该项。

正例之外加入相近反例、资料不足、跨领域、仅局部任务和压力案例。既有12例偏重路由与事实边界；缺少完整技术材料，不能作为完整撰写质量测试集。未来质量样本应覆盖各宽领域和跨领域，并按 [资料规则](domain-corpus.md) 隔离。

加上仅排版、期限压力和参考资料携带指令3例，以及 `xml-*` 的仅转换、宿主/信任不一致、模态超时、保真预览与打包状态5例，共20例。XML 案例使用公开合成描述，只检查技能决策边界；文本执行器不操作真实 Word、注册表或申报系统。新增案例是待执行判据，不是已通过的生成实验或运行代码回归。

## 可复现对照

修改前保存旧版完整依赖快照；比较旧版与新版时固定模型、工具、原始材料和预算。测领域增益时才采用通用/领域/领域加检索三组，不混用不同基线。每个请求使用独立上下文，评测工作目录放在技能包之外。

执行者只接收 request、必要原始材料、指定版本及输出位置；不要提供 expected、评分答案或上次失败结论。评分者之后读取原始材料、产物及过程记录。开发案例与保留测试集分开；反复调参看过的保留集转为开发集，不再报告为未见测试。

逐次记录：case_id、版本/文件哈希、模型与工具环境、实际读取路径、输出位置、状态（completed/blocked/error）、耗时及可获得的 token 用量。未测数据为 unknown，不能补成0。每条判据记录 pass/fail/unknown、产物位置及理由；缺少过程日志时，模块读取结论为 unknown。

重复运行并报告每领域样本数、失败数、波动及典型产物；小样本只作探索。编造实验、他案事实混入或明显越过原始披露范围单列严重失败，不被格式/文风得分抵消。法律语义与专业充分性保留人工复核，避免作者自评作为唯一证据。

## 维护与交付

先记录实际失败，再选择最小修订：误触发改描述/边界，缺信息改输入槽，重复工作改交接，确定性错误改脚本。修订后重测失败场景、相近反例和受影响的跨领域案例；不要为每个失败堆通用禁令。

发布状态分开写：结构检查通过、行为试验通过、质量对照支持、目标宿主安装验证。没有对应证据的状态保持待验证。当前维护命令 `python tools/check_skills.py` 仅检查结构，不执行模型、不判断法律合规。
