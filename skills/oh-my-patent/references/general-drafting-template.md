# 通用撰写模板

本模板规定信息组织方式，不预设行业、实施方案、参数或保护范围。可直接按材料写文本；使用工具时可用现有 CLI `template invention|utility|design` 生成骨架再填内容。缺项保留在工作记录，必要信息未齐时交付草稿。写作与支持方法见 [领域写法](drafting-method.md)。

## 共用信息槽

| 槽位 | 应填写的依据 | 检查问题 |
| --- | --- | --- |
| 保护主题 | 产品、方法、用途、组合物或外观的实际内容 | 是否与申请类型相符 |
| 技术问题/设计对象 | 使用条件与已有方案的具体限制 | 是否来自材料或已核实文献 |
| 核心手段 | 部件/步骤/成分/数据及其关系 | 每个必要特征是否有来源，能否实施 |
| 条件与范围 | 必要参数、边界、可选分支、工况 | 范围是否有支持；缺数字不一定有错，缺必要关系不能省 |
| 实施与验证 | 可复现的实施方式、附图、按需实验 | 具体细节能否支撑概括；不强制所有案件有实验 |
| 效果与区别 | 手段如何导致效果，现有技术对照 | 区分推断、实测与待验证；不把效果宣称当手段 |

## 发明与实用新型

起草前按 [权项规划](claim-planning.md) 确定独权范围与从属回退，分别核对本案支持和现有技术；共用一份规划，不由每个领域重复生成。

1. 权利要求：先确定必要特征和可支持的概括，再组织独权和从属回退层次。对每项建立“特征片段 → 说明书位置 → 本案事实”，检查全部特征及关系，不以匹配一段代表完整支持。
2. 说明书：技术领域、背景技术、发明/实用新型内容、适用时附图说明、具体实施方式。每个已加载领域模块只向相应槽位补充提问与审查条件。
3. 摘要：由已确认的技术问题、方案要点和用途归纳，按共用规则检查；不能引入权项与说明书均未披露的特征。
4. 图件：由真实结构/流程导出，与术语、标号和关系一致。实用新型按产品结构处理，算法不能仅更名为装置规避客体边界。

## 外观设计

围绕产品名称/用途、保护部分、设计要点、视图、代表图、省略理由、色彩要求组织简要说明与原图；具体由 patent-design 补充。外观不套用说明书与权利要求模板。技术方案和外观同时拟申请时分别准备材料并核对申请策略。

## 合并后的交付

文本路径汇总事实、支持关系及问题，交付草稿或审阅意见。选用工具时按 [内容审查](../prompts/08-content-review.md) 汇总结论，再以原 CLI 输出 Word 和交接包，不放宽其门禁。通用规则见 [中国规则说明](cnipa-2026.md) 及实际取得的适用原文；合法例外按具体事实说明，不将写作风格升级为绝对法定条件。
