# 真实项目交付复盘

本页记录一次真实项目从代码、业务确认、源码选材、真实截图到 Word 交付时暴露的问题，转成可复用门禁。它不绑定具体项目、框架或渲染后端，也不替代当期登记规则。

## 先冻结同一份事实

开始写手册或截图前，固定申请所用的代码身份。优先使用已提交的提交号；尚未合并的分支或 PR 只能作为候选版本，并明确记录其提交号、分支和验证日期。不要用“主分支代码 + PR 界面 + 未来功能”拼成一套材料。

把以下对象绑定到同一版本：

| 对象 | 最少记录 |
| --- | --- |
| 申请源码 | 提交号、工作树是否干净、源码扫描清单 |
| 实际运行 | 启动命令或入口、运行日期、软件版本 |
| 界面截图 | 来源提交、截图日期、知识库或测试实例、采集者 |
| 手册 | 软件名称、登记版本、实际核对版本和运行记录 |
| 申请字段 | 用户确认值；权属、日期、环境不能从代码推断 |

截图来自未合并分支时，在业务理解和手册核对记录中说明这一点。分支后来合并、改写或新增功能后，重新检查受影响页面和截图；旧截图不能继续证明新版本。

## 业务与字段门禁

先用真实页面、命令回显和项目文档建立业务模型，再写功能。候选文件、路由和组件名只能帮助定位，不能单独证明用户功能。将原始资料、候选内容、人工审核结果、正式知识和协作记录分开描述；不要把“已读取”“已投递”“收到回执”写成“已完成”或“已审核”。

用户给出软件全称、版本、简称和作者顺序时，逐字保留其决定。简称可以是空字符串；没有确定简称时不使用英文产品名代填。权属人、作者、署名顺序和开发方式必须来自用户确认。仍有占位姓名或身份材料缺口时，材料保持待确认，不因生成成功而升级为正式提交包。

## 写作与页面顺序

生成器给出的通用开场、功能总述和“未发现问题”不能替代人工阅读。按真实任务重写：用户从哪个入口进入、页面显示什么、执行什么动作、遇到什么限制、之后看到什么结果。重新检查相邻章节是否只是换词重复。

目录、功能介绍和页数要求是交付要求，不是版式装饰。先确认用户的页数范围和目录范围，再在实际 Word 中核对。目录字段可能出现“未找到目录项”或样式更新后失效；此时可以改为已核对章节的静态目录表，并在目录后分页。静态目录仍需与实际章节标题一致。

## 截图与隐私

只使用真实运行截图，不用生成图、宣传图或改绘控件代替。截图顺序必须与手册中的页面或流程顺序一致；图片替换后再次核对图片数量、顺序、图注和最终页图。

检查截图中是否有真实机器标识、内部消息、第三方页面标识、个人数据或无权展示的内容。发现问题时回到真实运行实例更换可公开数据后重新截图，不在图片上擦除后冒充原始页面。提交前由权利人确认展示范围。

## 源码与页数

源码行数、预估页数和实际页数分开记录。预估只用于选材；最终前后各 30 页、全部交存、每页行数和连续范围必须以真实排版结果核对。用户要求固定页数时，优先增加同一程序范围内有真实功能作用的完整文件，不补空行、不复制页面、不改写代码凑页。

选材发生变化后，重新核对源码哈希、文件范围、选择理由和此前确认的指纹。若真实前 30 页或后 30 页没有达到目标页数，按实际产出回到选材阶段；不能用“接近目标”替代交付要求。代码文档的页面必须来自源码，空白页和重复页不能充数。

## 交付前复核

至少完成以下检查，并把结果写入交付说明：

1. 软件全称、简称、版本、作者和权属顺序与用户确认一致。
2. 实际运行版本、截图来源和源码固定提交能够互相追溯。
3. 每个核心页面都有真实操作、可见反馈和对应截图，占位文字已清除。
4. 目录实际可见，章节与正文一致；用户要求页数时以最终排版页数为准。
5. 生成文档已重新打开或渲染，逐页检查文字、图片、表格、页眉和页码。
6. 源码文档页数与交存方式匹配，代码可回溯到原始文件。
7. 对第三方内容、机器标识和内部数据完成展示授权复核。
8. 已明确列出仍需用户补充的姓名、证件、日期、环境或其他事实。

“文件生成”“通过结构校验”“通过页数检查”“完成人工内容审阅”是不同结论。只有实际检查的范围可以写入交付说明；没有核查的项目保留未知。
