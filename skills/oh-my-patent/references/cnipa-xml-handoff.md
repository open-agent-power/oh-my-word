# 官方 XML 转换交接

先按 [任务范围](task-scope.md) 区分整案交接与仅格式转换。新案正式交接走 `final` / `handoff` 门禁；**仅转换既有稿件不以通过内容审查为前提**，不为取得 XML 机械填写 pass，仍如实保留支持、公开充分及其他待确认项。需要拆分时可普通 `build --split --strict --no-page-numbers`，但必须核对与用户指定原稿一致，不能用仓库旧稿替代。

1. 正式交接通过 final 后运行 `handoff`；仅转换使用核对过的单书副本。两种路径均使用无旧产物的新目录，保留原稿和哈希；插件加标记可能主动保存文件，不能直接操作原件。
2. 使用 https://cponline.cnipa.gov.cn “工具下载”的当前官方转换工具及手册，或系统申请文件编辑功能。输入兼容性以工具当前手册为准，不承诺任何 DOCX 均能无损转换。
3. 交接包 review-docx 对应权利要求、说明书、摘要、说明书附图和单独摘要附图；figures 保存原图；content.json 是内部内容核对表，不能上传冒充XML。
4. 按下述验收核对 DTD、逐段文字和图件，再分别检查本地预览及申报系统预览；无法正确转换时按官方编辑功能修复。变更内容须重新审查，转换完成不使原待审项自动通过。
5. 申请人与全部自然人发明人身份、请求书各项、委托、优先权等按案件填写。外观设计确认产品名称、视图和简要说明；软件方案不能改实用新型类型规避审查。
6. 保存转换器版本、文件哈希、校验及实际预览记录。请求书、签署、提交和缴费是另外的工作与授权；用户只要求转换时交付文件及缺口，不登录上传或代签提交。

整案工具状态沿用 draft → review_ready → official_conversion_pending；转换、内容审查、本地预览、系统预览和提交回执分别记录，不强制合并为单个「已完成」。允许「四书已生成、本地校验通过、内容待审、系统未预览、未提交」同时成立。不能把某个本地 JSON 的 true 当作国知局通过。

保留各次尝试的日志与产物，以一份当前摘要指向最新已核验版本；历史失败明确标注已被取代，不能在同一摘要中并列两个无时间边界的「当前状态」。原始审查文件在 evidence 中留存；复制后的 source-NNN 便于核对，其原路径引用不会被静默改写。交接目录不是可直接再次执行 final 的案件工作目录。

## XML 保真与交付验收

| 检查 | 接受依据 |
| --- | --- |
| 真实产物 | 官方工具本次生成、文件稳定可解析，XML 内容与预期文书相符；不能只信文件名、返回码或旧输出 |
| 官方 DTD | 保存 DTD 来源/版本/哈希、实际校验返回值及完整诊断；模型诊断与实例错误分开，解释见 [环境与转换](cnipa-official-tool.md#5-图号与资源故障) |
| 原始标记 | **先检查未归一化 XML 的私用区字符**（本次插件标记位于 U+E000–U+F8FF）；有残留先定位处理，不先剥掉再宣称零残留 |
| 正文 | 对照指定源稿逐段/逐块核对文字、次序、权项编号与引用、数字单位、公式和表格；摘要含标点不超过 300 字。仅使用已记录的空白/NBSP、源稿编号外壳等有限归一化，不能通删标点、数字或文字来制造一致 |
| 图件 | 核对全部图号、引用路径、顺序、inline 属性及实际加载；PNG 转 JPG 可能重采样和有损，不能要求图像哈希相等或宣称字节无损，须视觉核对细线、文字、裁切与缺图 |
| 原稿保护 | 转换后复核原稿哈希未变；插件标记、备份 DOCX 和重试只留在工作副本目录 |

逐段文字相同不能替代复杂对象及版面检查；图件哈希可证明同一文件，但不能证明 PNG/JPG 视觉等价。未覆盖的公式、化学式或排版保持未验证，不因纯文本案例成功宣称通用无损转换。

## 本地预览不是系统预览

官方 XSL 可能引用 `/dtdandxsl/…` 的站点绝对路径，直接打开 XML 白屏不一定表示内容无效。可在**仅含核验副本的隔离根目录**准备匹配资源，用绑定回环地址的 HTTP 服务预览，或本地 XSL 转 HTML。不要把案卷上级目录通过 HTTP 暴露到局域网。

为核验 HTML 增加 UTF-8 声明或准备资源，只能改变 QA 副本，不能为预览改写官方 XML/XSL。核对全部页面及图片，记录脚本/字体/资源失败及其影响；例如 MathJax/polyfill 404 时，纯文字和 JPG 正常不证明公式预览正常。资源受阻不静默下载不明替代脚本。

交付时说明本地实际核对范围和系统预览未完成项；申请系统最终分页、请求书与回执仍需另验。

## 压缩包白名单

仅收本次已核验的官方 XML 及其实际引用图片，保持相对目录和大小写。逐一解析图件引用、确认全部存在；解包核对条目、字节及 SHA256 与选定产物一致。文件数由本案实际图件决定，不硬编码「四 XML 加三图」。

不得混入源 DOCX、`bak*.docx`、事实/审查 JSON、脚本、修复备份、DTD/XSL、QA HTML、截图或日志。先排除其他文书/请求书缺口，不能把四书 ZIP 称为完整申请卷宗。打包不改变审查或提交状态。

## 转换源（DOCX）要清掉的项

《关于规范提交专利电子申请的指引》禁止域对象、文本框、自选图形等。handoff 拆出的文件应满足：

| 项 | 要求 | 为什么 |
| --- | --- | --- |
| 段落编号 `[0001]` | 不得出现 | XML 段号由系统生成。注意是**半角方括号**，用全角 `【】` 去匹配会误判成 0 条 |
| 页脚 `PAGE` 域 | 清空页脚 | 域对象属禁止项；XML 没有页脚概念，页码由系统按页生成 |
| 水印 / 宏 / 嵌入对象 / 超链接 / 控件 / 批注 / 修订 / 文本框 / 自选图形 / 浮动图 | 不得出现 | 同上 |
| 图片 | 300DPI JPG/TIF，图内无图号文字，「图1」以文字形式在图片外，单页内不跨页 | 转换器对图片格式与图号位置敏感 |
| 拆分遗留的孤儿图片 | 删除 | 非正文内容；**按 `document.xml.rels` 里实际被引用的 rId 判断，不能按文件名删**（按文件名删会连带删掉正文还在用的图） |

**「带页码的打印稿」与「能转 XML 的转换源」是两个目标**，不要指望同一份文件兼得：
前者要页脚页码（纸件规定），后者必须没有域对象。

## 100001~100004 模板不是电子表单

官方「表格下载 · 通用类」的 `100001权利要求书` / `100002说明书` / `100004说明书摘要`：
第 1 页只有页眉标识（如「权利要求书 / 100001 / 2023.03」，约 30 字）、**0 个表格**，
第 2 页是「注意事项」，并写明「首页用此页，续页可使用同样大小和质量相当的白纸」。

结论：它们是**纸件首页的版式基准**，不是填格子的电子表单。用户问「官方有模板，
我们直接写是不是错了」时，回答「版面照它、正文不必填进去」，并区分**表单类**文件
（110101 请求书、100006 补正书等，要逐栏填）。

注意别把两套「模板」混为一谈：WORD转XML编辑器页面提供的是**五书模板文件**（带转换器所需标记），
与纸件首页模板用途不同。

## 摘要附图指定方式待核实

本项目已验证的单书转换路径输出 100001~100004，未验证独立「摘要附图 XML」编码，不能编造第五种编码，也不能因此删除审阅用摘要图或宣称系统不再要求摘要附图。

保留指定的说明书图号；是否在请求书中指定、当前栏位及操作方式，须查当前官方手册/系统或向电子申请咨询确认。历史记录中的「第 24 栏」不是本指引已核实的通用规则。无法确认时明确待核实，不用本地转换成功代替系统验证。

## 已核实的官方操作入口

[WORD转XML编辑器及模板手册](https://cponline.cnipa.gov.cn/GzfwYwblGlwhTMVC/GzfwYwblGlwhT/selectToolsById?weihuRid=157)。2026-09-30核查页面显示 Windows 10及以上，最新安装包标为 V4.3_2_20251218（页面写更新日2025-12-18）；实际使用仍检查新版本。

官方五书模板操作说明给出的路径：在模板对应区域编辑/粘贴说明书摘要、摘要附图、权利要求书、说明书和说明书附图；用“专利处理→添加标记”；将光标放入一书内容中，再用“XML生成”生成对应文件。模板和转换器会添加自身所需标记。本项目不伪造这些专有标记，也不把普通Word当成已转换文件。

说明书内容区使用稿件真正技术正文，不复制本工具审查报告、证据ID和交接状态。按当前手册确认文书标题/页眉、段落标记、复杂对象及图片处理。通过官方XML预览逐项核对后才提交。
