# CNIPA 版面与交付：实测结论与踩坑清单

记录日：2026-10-25。来源是一份真实发明申请（说明书 7782 字、权利要求 12 项、3 幅附图）
从「Word 审阅稿」推到「符合国知局版面 + 可转 XML」的全过程。

本文只写**能复现或能引原文**的结论。凡是推断、传闻、未验证项，都单独标注，
不与已核实事实混排。

---

## 一、版面口径：官方给的是毫米，不是「字号」

### 1.1 两套说法，上限只在一处

| 来源 | 字高 | 行距 | 适用范围 |
| --- | --- | --- | --- |
| 《专利审查指南》第五部分第一章 5.2 | 不低于 3.5mm | — | 法定下限 |
| 官方 `100002说明书` 标准表格背面「注意事项」 | 3.5~4.5mm | 2.5~3.5mm | 纸件实际执行口径 |

审查指南只规定下限，**4.5mm 上限出自标准表格的填表说明**。纸件递交按带上限这一档做，
因为你无法预知受理窗口按哪一档核对。

### 1.2 字号 → 墨迹字高（宋体，Word 渲染后实测）

| 字号 | 墨迹字高 | 结论 |
| --- | --- | --- |
| 12pt（小四） | 约 3.9mm | 合规，正文首选 |
| 13pt | 约 4.3mm | 合规，**纸件标题上限** |
| 14pt（四号） | 约 4.7mm | 超 4.5mm，不可送审 |
| 16pt（三号） | 约 5.6mm | 超标 |
| 22pt（二号） | 约 7.5mm | 严重超标 |

「名义字号 ≠ 墨迹字高」。任何按 pt 直接判定合规的说法都不可靠，必须渲染后量。

**工具当前默认**：正文 12pt、文书名称与发明名称 13pt、章节标题 12pt —— 均在区间内，
由 `tests/test_layout_baseline.py` 钉住。此前默认标题是 22/16pt，等于每份产物都超限。

### 1.3 行距 → 行间空白（同一份说明书，只改 `styles.xml` 的 `w:line`）

| 行距 | 基线间距（中位） | 行间空白（中位） | 页数 | 结论 |
| --- | --- | --- | --- | --- |
| 1.25 倍（`w:line="300"`） | 6.86mm | 2.96mm | 7 | 合规 |
| 1.5 倍（`w:line="360"`） | 8.21mm | **4.32mm** | 9 | **超 3.5mm 上限** |

**为什么容易算错**：Word 的「多倍行距」以**字体单倍行高**为基数，宋体单倍行高约
1.3×字号，不是 1×字号。按「倍数 × 字号 − 字高」折算，1.5 倍会得出约 3.4mm 的假结论，
实测是 4.32mm。这个错误曾在本文档前身里存在过，导致生成器默认值取 1.5，
每份产物都超限且多排 2 页。

**测量方法**（唯一可信的做法）：docx → PDF → 300dpi 位图 → 按行扫描墨迹带 →
`行间空白 = 相邻墨迹带基线间距 − 字框高度`。用 `span.bbox` 的 `y0` 差值、
或在 Word 里看「行距：1.5 倍」都不行，前者含字形盒，后者是设定值不是结果。

### 1.4 页码：三个条件缺一不可

1. **各部分分别编号**，不是全文连号（权利要求 1~N、说明书 1~N、摘要 1、附图 1~N）。
2. **每页下部页边上沿、左右居中。**
3. **页码下沿距纸张底边 15mm。**

工程实现上的三个坑：

| 现象 | 原因 | 做法 |
| --- | --- | --- |
| 页码贴纸边 | `footer_distance` 默认 10mm | 设 `Mm(15)`；它直接决定页码墨迹下沿位置 |
| 页码整体右偏约 5mm | 左 25mm / 右 15mm 使**版心中心**右移 5mm，而要求是**纸张居中** | 页脚段落加 10mm 右缩进补偿（实测残余偏移 <0.5mm） |
| 增删页后编号全错 | 页脚写死数字 | 必须用 `PAGE` 域；域的 `separate` 与结果占位不能省，否则部分渲染器显示空白 |

**「版心居中 ≠ 纸张居中」是本案最容易漏的一条**：页边距本身不对称，任何居中项
（页码、页脚、某些表格）都要单独补偿。

### 1.5 权利要求书的隐性硬规则

来自官方 `100001权利要求书` 背面「注意事项」，比审查指南正文更具体：

- **每一项权利要求仅允许在结尾处使用一个句号**。分项列举的步骤/部件，段末用**分号**，
  最后一项才用句号。
- **不得有插图**（化学式、数学式可以）。
- 科技术语须与说明书**逐字一致**。
- 每页下框线居中顺序编写页码。
- 编号前不得冠以「权利要求」「权项」。

## 二、官方 `100001~100004` 模板到底是什么

### 2.1 结论

它们是**纸件首页的版式基准**，不是「填格子」的电子表单。

| 文件 | 页数 | 第 1 页内容 | 表格数 |
| --- | --- | --- | --- |
| `100001权利要求书` | 2 | 仅「权利要求书 / 100001 / 2023.03」30 字 | **0** |
| `100002说明书` | 2 | 仅「说 明 书 / 100002 / 2023.03」31 字 | **0** |
| `100004说明书摘要` | 3 | 仅「说明书摘要 / 100004 / 2023.03」22 字 | **0** |

第 1 页只有页眉标识，正文区整块留白；第 2 页（摘要第 2~3 页）是「注意事项」。
真正的旁证是「注意事项」里的那句：**「首页用此页，续页可使用同样大小和质量相当的白纸」**
——这句话只在纸件打印装订场景下成立。

### 2.2 因此有两件事不能搞反

- **不要**把正文往 `100001` 里填。它没有栏位，填进去等于自己重排版面。
- **要**区分两类「模板」：
  - 版式类（`100001`~`100004`）：给纸件首页用，正文自撰。
  - 表单类（`110101` 请求书、`100006` 补正书、`100007` 委托书）：**有栏位、要逐项填**。

### 2.3 下载页的分类也印证这一点

`服务 → 表格下载 → 与专利申请相关 → 通用类`。同栏目还有「电子申请专用」「PCT」等分类。
`100001`~`100004` 在「通用类」，说明它们对所有递交方式通用，不是电子申请系统的必填表单。

## 三、2026-01-01 起：提交件是 XML

| 要点 | 内容 |
| --- | --- |
| 需转 XML | 100001 权利要求书、100002 说明书、100003 说明书附图、100004 说明书摘要 |
| 请求书 | 表格类文件，**在系统里填写**，不走转换、不上传 |
| 工具 | cponline「工具下载」→ WORD转XML编辑器，V4.3_2_20251218（2025-12-18 更新） |
| 离线要求 | **Windows 10 及以上**；MS Office 2013+ 或 WPS 专业版 2015+（2026-10-25 复核页面） |
| Word/PDF 的地位 | 只能作为「参考文件」另传，**不是申请文件** |

### 3.1 转 XML 前必须清掉的项

依据《关于规范提交专利电子申请的指引》：

- **说明书不得有任何形式的段落编号**（`[0001]`）。XML 里段号由系统生成。
  注意是**半角方括号**，用全角 `【】` 去匹配会误判成 0 条。
- **不得含域对象**。页脚 `PAGE` 域属于域对象 → 转换源应清空页脚。
  XML 没有页脚概念，页码由系统按页生成。
  **2026-10-25 实测补充**：带 `PAGE` 页脚的交接包文书，官方工具仍能转换成功，
  页脚不进 XML；但「能转」不等于「合指引」，送审仍建议先删页脚。
- 同样禁止：水印、宏、嵌入对象、超链接、控件、批注、修订、文本框、自选图形、浮动图片。
- 图片：300DPI 的 JPG/TIF，单页内不跨页，图内不得有图号文字（「图1」以文字形式在图片外）。

**页码的处理**：审阅/打印稿带页码（合规必需），`handoff` 拆出的转换源默认也带页码，
实测可转换；若提交端要求彻底无域，转换前删页脚即可，不必重排版面。

### 3.2 待确认项（不写进规则）

- **摘要附图没有独立 XML 编码**。上传清单只有 100001~100004。实务做法是在请求书
  第 24 栏填「指定说明书附图中的图__为摘要附图」，即**填图号**。
  这一条没有在本次核查的官方文件里直接读到，**属待确认**，别写成既定规则。
- 官方转换器已于 **2026-10-25 实机跑通**（真 Word 365 + 官方 V4.3），四书转 XML 且过官方 DTD；
  细节与坑见第七节。合并成单份的五书文档仍只识别出权利要求书，这一条仍属待解决。

## 四、工程侧的踩坑清单（可复现）

1. **`pPr` 子元素必须按 schema 顺序**：`spacing` 要在 `ind` / `jc` 之前。
   追加到末尾会被 Word **静默忽略**，且导 PDF 照样成功 —— 所以「能打开、能导出」
   不能证明改动生效，必须回读 XML 或量渲染结果。

2. **段落间距是覆盖，不是累加**：段落写了 `spacing after=120`，
   会**覆盖**样式里的 `after=160`，净效果是变小。想净增 6pt 必须写 `160+120=280`。
   改前先查样式原值。

3. **量版式一律量渲染后墨迹**：`span.bbox` 含字形盒，`y0` 差值不等于行距；
   Word 显示的「行距倍数」是设定值不是结果。

4. **新分节会继承上一节的分页属性**：本案权利要求 8→9 之间出现整页空白，
   根因是第 9 项继承了 `pageBreakBefore`，不是间距问题。查继承属性，别先调间距。

5. **删 docx 里的图片不能用文件名匹配**：正文通过 `rId` 引用 media，按文件名删会
   把还在用的图一起删掉（本案 437KB → 36KB，三张图全丢）。必须解析
   `document.xml.rels` 里实际被引用的 `rId` 再删。

6. **字符单位首行缩进比 twips 稳**：`w:firstLineChars="200"` 在 WPS/Office 下表现一致，
   `w:firstLine="480"` 在字号变化时会漂。

7. **生成器的默认值就是交付质量**：默认 1.5 倍行距 + 默认不出页码，
   等于每个不传参数的用户都拿到不合规产物。不要靠使用者记参数 —— 改默认值。

8. **Windows 上 Word 开着文件时保存会 `PermissionError`**：另存新名再做，别原地重写。

9. **改 run 的字号不等于改样式**：python-docx 默认模板的 `Heading 1` 样式是 **14pt**
   （墨迹约 4.7mm，超上限）。只给 run 设字号时样式仍是 14pt，任何没显式设字号的
   标题段落都会漏出超限字号。改字号要同时把样式改掉，并在生成后回读
   `Document(path).styles['Heading 1'].font.size` 核对，别看代码里的常量就放心。
   （2026-10-25 实测：常量改到 13pt 后，样式仍是 14pt，直到把样式一并修补才一致。）

## 五、流程侧的教训（比技术坑更贵）

1. **项目内文档不是法规原文。** 本案曾拿项目 `docs/` 里的二手结论当依据，
   被要求「去官网核对」。核实后发现：字高上限、页码 15mm、每项一个句号
   这三条都不在项目文档里，而在官方表格的注意事项里。**规则类结论必须有官方 URL 或原件。**

2. **用户看到的「一小段空白」，根因常在属性继承，不在显式设置。** 先怀疑继承和默认值。

3. **自己写的校验通过，不等于合规。** 结构测试能证明「代码按设计跑通」，
   证明不了「版面符合国知局要求」。后者只能靠渲染后实测 + 官方文档比对。

4. **不编造身份信息。** 请求书里的姓名、身份证号、地址、电话一律留空给本人填，
   交一份「填写信息清单」比交一份填了假数据的表安全得多。

5. **交付包要能自证。** 每个结论配一条可复核证据（页数、字数、表格数、实测毫米数、
   官方 URL），否则下一次讨论又要从头争。

## 七、官方工具实机跑通（2026-10-25）

这一节是「能转成 XML」的第一份真实证据：真 Word 365 + 官方 WORD 转 XML 编辑器 V4.3，
把交接包拆出的四书转成 XML，并用官方包内 DTD 校验通过。

### 7.1 安装：管理员 + 两个非显然条件

| 现象 | 原因 / 处理 |
| --- | --- |
| 非管理员 `msiexec` 报「只能从 bootstrapper 运行」 | MSI 的 LaunchCondition 是 `SETUPEXEDIR OR (REMOVE="ALL")`，传 `SETUPEXEDIR=<包目录>` |
| 过了启动条件仍 1603、日志「写入 `C:\ProgramData\PatentTool\…\scaleimage.js` 出错」 | 安装程序把共享数据写成 Users 只读，普通权限写不进，**必须管理员** |
| 失败半装后管理员也删不掉 | 14,578 个只读文件，`Remove-Item -Recurse` 报「目录不是空的」；用 `rd /s /q` / `\\?\` 删除并重试 |
| 装完 Word 无「专利处理」菜单 | 插件清单签名证书 **2026-07-14 到期且无时间戳**，VSTO 报「签名清单或证书未知」 |

插件信任的当前用户级解法（无需再提权）：在
`HKCU\Software\Microsoft\VSTO\Security\Inclusion\{GUID}` 写 `Url`
（**指到 `PatentTool.vsto` 文件，指目录无效**）、`PublicKey`（清单 `KeyInfo` 里的
`<RSAKeyValue>`，不是证书公钥）、`Name`。写完 `COMAddIns(...).Connect` 即为 True。

**这属于发行方打包缺陷**：证书过期 + 无时间戳 → 2026-07-14 之后的全新安装都会加载失败，
不是本机环境问题。用户遇到「装完没菜单」应优先查这里。

### 7.2 转换：先标记，再按单书转

- 顺序必须是「一键添加标记」→「单书XML转换」。直接点「五书XML转换」时，
  本次的合并稿（单节、无硬分页）被整体当成权利要求书，说明书/附图/摘要都进了 claims。
- 每份文书单独转换，产物是 `100001`~`100004` 目录 + XML + 附图 JPG
  （官方工具会把 PNG 附图转成 JPG）。
- 预览/XSL 依赖文档目录旁的 `dtdandxsl`（官方 `dtdandxsl.zip` 解出），
  缺了会报「拒绝访问 …/dtdandxsl/cn-application-body-20080416.dtd」。
- 标记本身是私用区字符（U+E000–U+F8FF），转换后从 XML 里剥掉；
  做正文保真核对要先剥这些字符，否则会误判「全文都不见了」。

### 7.3 实测结果（公开授权文本 CN110008257B，非真实交底）

| 文书 | 产物 | DTD | 保真 |
| --- | --- | --- | --- |
| 权利要求书 | 100001.xml 14.7 KB | 通过 | 17/17 项逐字一致 |
| 说明书 | 100002.xml 77.4 KB | 通过 | 24,349 字一致；仅 5 个章节标题的 `【】` 被去掉 |
| 说明书附图 | 100003.xml 0.7 KB + 2 JPG | 通过 | `figure num=0001/0002`、`img inline=yes` |
| 说明书摘要 | 100004.xml 1.1 KB | 通过 | 266 字完全一致 |

版面侧同时在真 Word 里量过：A4 210×297、页边距 25/25/15/15、12pt 宋体、
行间空白 2.62mm、页码居中偏移 0.00mm、页码下沿距纸底 14.96mm、全黑白。
