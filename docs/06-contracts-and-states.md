# 现行契约与交付状态

## 产品语义（2026-10-24）

产品统一称 `word-skills`，核心是领域写作 Skills。`oh-my-word` 保留为仓库名称，`oh-my-patent` 保留为专利能力、兼容包及命令名；本轮不重命名路径、命令或旧案件。主要使用者是基于真实材料起草/修改文稿的人与 Agent。用户决定目标并提供真实业务确认，Agent 理解、写作和复核，工具执行机械处理；需要专业判断的结论由相应责任人核验。

| 术语 | 统一含义 | 依据与归属 |
| --- | --- | --- |
| Skill | 任务范围、写作方法、适用规范、案例和审阅指导 | 各域 `SKILL.md` 及所需参考；存在指令不证明模型遵从 |
| 规则 / 参考 | 规则限定适用要求，参考提供方法、术语或对比材料 | 原文、版本、日期与适用范围；不自动成为本案事实 |
| 项目材料 | 本案原件、源码、图件、记录与用户提供的信息 | 保留来源位置和未知项；提取文本不是原件的无损替代 |
| 事实 / 判断 | 事实需核对来源；解释、推断、提案及未确认项明确分开 | Agent 逐陈述核对；真实引文不自动支持全部结论 |
| 文稿 | 可修改的正文或审阅意见，包括文本草稿及工具中间稿 | 由任务决定格式；文本路径不强制本项目 JSON 或 CLI |
| 交付物 | 本次承诺交付的文本、文件或材料包 | 写清实际完成范围、检查依据、未完成项；生成文件不等于业务验收 |
| 工具 / 适配器 | 按选定任务提供摄入、校验、检索、制作或交接 | 复用已有实现并做必要转换；不替 Agent 生成事实或专业结论 |

来源责任保持分开：领域登记以 `registry/skills.yaml` 为准，写法以各域入口为准，规范以适用原文为准，项目事实以实际材料为准，执行/交付状态以相应工具记录为准；上游采用身份以 `upstream.lock.json` 及许可证为准。

## Skill 依赖与能力声明

注册表继续使用 v1：`dependencies` 表示该 Skill 当前路径不可省略的其他 Skill；新增可选 `optional_dependencies` 表示选择相关任务或制作路径时才使用的 Skill。两者引用已登记名称，不允许重复、自引用、重叠或未知名称。旧记录不含可选字段仍可读，缺失列表按空列表解释。

这些是 Skill 之间的使用关系，不是 Python 包依赖、安装器、自动加载指令或环境健康检查。完整资源的本地引用仍由结构检查核对。总入口按目标选择其他 Skill，登记为可选组合；技术与软著的 `word-document` 仅为制作路径依赖。专利沿用自己的可选 CLI，不强行依赖通用 Word Skill；项目申报当前入口仍要求制作链路，其依赖保留，不能推断为已完成同样解耦。

`skills list` 和 `route` 的 JSON 保持 `schema_version=1` 及原选择/生命周期字段，新增依赖分类；源码与 wheel 注册表快照必须一致。`route` 文本输出原 `status: ready` 改为 `status: matched`，只表示入口匹配，不表示已执行；解析自动化应使用 `--json`。`implemented` 是实现登记，`focused` / `baseline` 是模式投入范围，均不能证明当前环境可用、材料充分、写作质量或业务成功。

## 完成含义与旧状态对应

下表统一对外解释，不新增或合并持久状态，不给文本草稿制造工具通过记录。

| 对外说明 | 需要说明的完成内容 | 现有工具状态与边界 |
| --- | --- | --- |
| 已匹配入口 | 选择了哪些 Skill 及其任务范围 | 仅路由结果；没有写作、校验或交付执行 |
| 文本草稿 / 审阅意见完成 | 已回应本次任务，附必要来源、支持笔记和可见缺口 | 可以没有工具状态；不等于机器检查、正式材料完成 |
| 已做某项检查 | 实际检查者、具体范围、依据、结果和残留问题 | 内容/版式/哈希等分别说明，不能只写“全部通过” |
| 文件已生成、待审阅 | 产物存在并保留实际生成记录 | 通用 `draft` / `awaiting-review`，不等于内容或页面已经看过 |
| 本工具审阅交付就绪 | 对应工具契约和复核记录齐备 | 通用 `reviewed`、专利交接说明中的 `review_ready` / `official_conversion_pending` 及软著包 final 门禁各有含义，不能互认，也不证明事实/专业结论正确 |
| 已转换 / 已提交 / 已受理 | 对应外部系统的真实操作结果、回执和范围 | 本地生成、工具 final 或 hash 不产生这些结论；本项目不自动提交 |

同案文字/版式修改复用有效来源，实际变化使有关审阅失效；不重复制造用户确认或把等待当确认。现有拒绝、变化失效和正式交付检查保持不变。

## 现有数据契约

稿件、来源索引、账本和片段继续采用 JSON v1；models.py 的 validate_*_v1 检查现行传输格式。CaseManifest/Fact/Requirement 等 dataclass 是扩展 DTO，不替代全部现行序列化。

新增可选 case_id/document_id：分别标识同一材料项目与其文档。prepare 为软著 case 生成持久标识，源码和手册使用不同 document_id；draft/audit/hash/build_id 仍独立，不能把一份文档的审阅套用到另一份。旧 v1 未携带标识的案例仍兼容。

通用持久状态：blocked（构建前拒绝）、failed（制作/检查失败）、draft（未完成审阅或明确草稿）、awaiting-review、reviewed。`business-pending` 是内部状态：共享制作成功后须绑定业务原件及校验审计，才可进入 awaiting-review；不能直接 review-init/finalize。

copyright package 包含两份独立子交付。正式准备包只有在两个子文档分别真实审阅、源码/手册/填写辅助及审阅记录哈希完整时才能 package-finalize。此状态不表示已提交或具备登记资格。

明确 preview 用途可将权属/完成日期等缺口列为待确认，不能放宽源码哈希、选段、软件名称/版本和手册来源检查。子文档强制 draft，根包 purpose=preview；现有 review-init 和 package-finalize 都拒绝把它升级。确认字段后须重新构建正式准备包。

业务原件、来源、模板、辅助文件、子文档、审阅或生成器变化应使对应旧证据失效。旧产物不原地覆盖；哈希证明身份一致，不能证明语义或权属。

## 图文手册扩展

v1稿件新增可选image块：text为图注、path为case内PNG/JPEG、sha256为原件哈希；图片复制到审计并参与构建身份，旧paragraph/table/code保持兼容。图注需要证据引用，图片语义仍需审阅。段落可携带heading_level或monospace以保留手册结构。copyright软件身份由业务校验后投影到页眉，未知权属不写入技术手册正文。
