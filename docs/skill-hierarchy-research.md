# 总览与领域子 Skill：调研及改进决定

日期：2026-10-13。目标：优先建立通用模板和可扩展的领域体系，不选择单一领域试点。本文替代上一轮评估中“先做固废材料试点”的建议；上一轮具体门禁问题仍有效。

## 调研结论

建议采用“通用总览 → 申请类型/阶段判断 → 按技术贡献组合领域模块 → 共用事实及审查 → 文书输出”。父子关系由本项目显式路径与接口约定实现。Agent Skills 标准规定 SKILL.md 与按需加载资源，但不保证嵌套目录会自动注册或父 Skill 会自动调用子 Skill。[Agent Skills 规范](https://agentskills.io/specification)、[官方设计说明](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)。

该方案与目前仓库的轻量 CLI 适配：模型承担判断和撰写，Python 继续负责已有解析/格式/证据结构。无须为每个领域复制生成器或启用新 Agent。完整包保留相对引用即可由总览加载；宿主安装和触发成功须另测，不能从文件存在推定。

| 设计问题 | 本轮决定 | 原因 |
| --- | --- | --- |
| 单一大 Skill 还是分层 | 通用入口+短目录+按需子 Skill | 防止所有案件加载全部领域细则，降低维护重复 |
| 单选行业还是可组合 | 类型、技术贡献、阶段分开；主领域+必要辅助领域 | 医疗设备外观、AI器械、材料器件等不能按行业词单选 |
| IPC/CPC 是否直接成为子 Skill 树 | 作为检索/复核标签，不一对一路由 | 技术分类用于专利分类检索；写作与披露需求可能横跨分类。[WIPO IPC](https://www.wipo.int/en/web/classification-ipc) |
| 每个领域独立事实账本 | 每案共用一个账本和统一审查 | 避免交叉方案的参数、术语、接口和证据相互矛盾 |
| 通用模板是否固定所有细节 | 固定信息槽，按类型/必要性填写 | 说明书支持与充分公开须结合实际方案，不能预填常用参数。[专利法第26条](https://www.cnipa.gov.cn/art/2020/11/23/art_97_155167.html) |
| 提交后补材料 | 单独标阶段并核对原始范围 | 新例子或新事实不自动使申请后修改合法。[专利法第33条](https://www.cnipa.gov.cn/art/2020/11/23/art_97_155167.html) |
| 增强资料是否等于训练 | 分开 Skill 维护、检索增强、参数微调 | 三者更新的对象不同，需要各自证据与验证 |

## 中国专利规则对架构的影响

发明/实用新型与外观设计的文件结构应先分开。方法保护、结构保护、外观保护不可由行业名称决定。多项从属引用、局部外观、特定生物材料保藏、序列和遗传资源等条件适合按案件路由到对应提示，而不向全部稿件堆全部检查。[实施细则](https://www.cnipa.gov.cn/art/2023/12/21/art_98_189197.html)。

AI 可作为跨领域技术组成。2026 生效的局令84号分别强调模型构建/训练与场景应用的必要披露；一个案件可以同时涉及两类。应按真实改进选择模块，关键词命中或把算法改写成若干“模块”不能证明充分公开。[局令84号](https://www.cnipa.gov.cn/art/2025/11/14/art_99_202568.html)。

通用层保留 XML 交接和真实性边界；领域模块不能放宽这些要求。领域数据输入也不会让当前 CLI 获得官方转换/提交能力。[XML通知](https://www.cnipa.gov.cn/art/2025/11/12/art_75_202551.html)。

## 本轮已经落地

- 主 SKILL 改为总览入口，明确显式路径加载、多领域合并、未知领域回退和阶段判断。
- 增通用撰写模板、路由记录规范、领域目录与子 Skill 扩展契约。
- 增五份宽技术领域子 Skill：软件/AI、机械、电子通信、化学材料、生物医药；另增外观设计文书模块。这是初始覆盖，不代表穷尽所有专业。
- 将共用事实/审查指令中的特定案例参数改成通用数量、条件与量纲检查，把软件/AI披露细节移入按需子模块。
- 规定领域结论映射到现有13项检查，避免只改 prompt 却生成 CLI 不接受的 checks ID；必要信息不足保持待审。
- 增资料角色、来源卡和多领域对照评测约定，附12个路由/边界案例。

## 后续如何定向积累资料

每个领域模块可附少量经核实的披露反例和写作经验；规模化文献应进入带来源、日期、角色和版本的案例库，起草时按实际技术贡献检索。资料越多不必然越好，低质量或错角色资料可能把他案事实带入新案。优先积累申请文本、授权文本与审查过程的对应关系，区分采纳了什么、修改了什么以及原因。

检索增强原论文描述了检索外部知识与生成结合的方式，支持将知识更新与模型参数分开设计；它不证明本项目的专利稿质量或授权率会提高。[RAG 原始论文](https://arxiv.org/abs/2005.11401)。当前只落地资料使用契约，尚无内建向量检索或微调服务。

领域效果应在统一输入、模型/工具条件下，对照通用流程、加领域模块、再加检索三组；按专利族和时间隔离参考与评测材料。至少分开报告路由错误、无依据事实、必要特征覆盖、说明书支持、公开充分性、引用准确性和人工修改成本；重复试验并记录评审分歧。[Agent 评测方法](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)。

## 验收与下一轮优先级

本轮验收为 Skill 结构、引用路径、目录覆盖和场景规则的静态检查，结果见 `.agent/RESULT.md`。12个案例是行为评测输入与判据，不是12次实际生成试验；没有证据时不报质量提升。

下一轮优先修上轮已复现的 Python 门禁问题：首项权项误判、多项从属引用漏检、渲染参数范围和证据覆盖不足。之后若要把领域路由/审查版本纳入机器门禁，再设计 schema 迁移和兼容；当前 Agent 记录不构成强制校验。新领域应凭实际需求新增，不按分类号批量生成空壳 Skill。
