# 任务范围与模块交接

先明确用户本次需要的产物，再选择最小必要流程。领域识别沿用 [路由规则](domain-routing.md)，无需每次重读全部领域。

| 请求 | 必要工作 | 完成的含义 |
| --- | --- | --- |
| 新案文本起草/审阅 | 写前来源、领域写法、对应领域、事实和逐特征支持复核；可用普通笔记 | 文本草稿或审阅意见，不产生工具定稿状态 |
| 工具审阅稿/定稿与交接 | 总览工具链路、对应领域、事实及内容审查 JSON、真实制作检查 | 按实际完成阶段交付；官方转换/提交另验 |
| 材料梳理/专利点挖掘 | 读材料、标来源与缺口、相关领域判断 | 候选方案和提问；尚未完成申请文件 |
| 修改某个权项或实施例 | 读取相关正文、事实、引用关系与对应领域；复核受影响支持关系 | 局部修订；原审查不得直接沿用到修改稿 |
| 仅转换/排版 | 使用既有 CLI，核对实际文书与图件；发现实质风险时明确列出 | 格式处理；不自动声称实质合规 |
| 已申请后的修改/答复 | 先获取原始申请、当前文本及审查意见/程序信息，再分析修改依据 | 无原始范围时只能列问题，不能补造合法修改依据 |
| 只解释专利术语 | 直接答复，必要时核对官方来源 | 无需创建事实账本或整案目录 |

主模块负责统一稿件；辅助模块只提交与本案有关的补充。将以下信息写入已有案件摘要或审查证据，不为每个模块另建报告：

- 输入：具体材料及位置、待处理技术特征、已知/未知条件。
- 结论：该领域改变了哪些披露或审查判断，以及对应来源。
- 交接：建议修改的位置、关联权项/图件/接口、尚待确认问题、受影响的现有检查项。

只输出被材料触发的内容；辅助模块不重复生成整份申请。结束条件是本次请求的产物已完成且缺口清楚；遇到关键材料缺失，交付可完成部分和具体问题。Skill 不改变外部动作授权或工具能力。
